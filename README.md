# Awesome-Game-Tools
For GPR-100-01

In this Repo I will be listing 10 interesting or useful game tools!

1. UPBGE is the tool I'll be doing my presentation on. Its a community run updated version of the now discontinued blender game engine. While UPBGE and BGE both had their flaws UPBGE is definitely better and more updated. That being said UPBGE runs its code in python and has a whole plethora of issues in regards to performance. UPBGE is more of a novelty based around the idea of having a game engine inside blender as opposed to an actual practical game engine. There are still lots of cool projects made with UPBGE check out Sword of Symphony.
2. Aseprite is a tool used for 2D pixel art in games. I've used it myself and many of my friends have recommended it to me over the years. Its pretty beginner friendly and very cheap for how good it is.
3. Mixamo is an asset library with a large selection of free 3d models you can download and use as you wish. I used this back when I was experimenting with 3d games in my senior year of highschool.
4. Blender is a 3d modeling tool that I was never great with but it is another thing I used for fun! I watched a lot of tutorials and would love to pick it back up some day because of how detailed you can get. Blender has the capacity to create literally anything you can think of though unfortunately the interface is not beginner friendly at all as a result.
5. Unity is probably one of the most well known game engines out there and is what I used when I first started experimenting with making games. It uses C# for its scripting and has a huge amount of tutorials and resources available online. Unity is pretty beginner friendly compared to some other engines but it can definitely become complicated once you start working on bigger projects.
6. Unreal Engine is another extremely popular game engine that is mostly known for being used to make high quality 3D games. One of the coolest things about Unreal is its visual scripting system called Blueprints which lets you create game logic without having to write as much code. It can be pretty intimidating at first but there are a ton of resources available for learning it.
7. Godot is a free and open source game engine that has become a lot more popular over the years. It uses its own programming language called GDScript which is pretty similar to Python and makes it relatively easy to learn. I think Godot is especially interesting because it is completely free and still has a lot of the features you would expect from a professional game engine.
8. RPG Maker is a game development tool specifically designed around making role playing games. It is much more beginner friendly than something like Unity or Unreal since you can make a lot of a game without knowing how to code. I've always thought it was interesting because it shows how much you can accomplish with a game engine that is designed for a very specific type of game.
9. Tiled is a tool used for creating 2D tile maps which can then be imported into different game engines. It is especially useful for games that use pixel art or have large environments made out of repeating tiles. It is a pretty simple tool compared to something like Blender but it can save a lot of time when designing 2D game levels.
10. GIMP is a free image editing program that can be used for creating and editing textures, sprites, and other assets for games. It is kind of like a free alternative to Photoshop and has a huge number of features despite being completely free. The interface can take some getting used to but it is a really useful tool if you want to make your own game assets instead of downloading everything from somewhere else.

For this assignment I will be listing 5 different career paths under the umbrella of game development!

1. Audio designer is the role responsible for everything sound related often including music. They use various softwares and sometimes real world equipment to create all the sounds and audio in your favorite games.
To me sound design has often been what separates a good atmosphere from the very best. Look at games like Battlefield 1 that are heavily praised for their immersion and I think the incredible sound design is the reason for this immersion.
When it comes to career pathways the best way to get into the position of an audio designer is often by having some experience or education relevant to the software in use for the project. If you have that you may secure a position as a junior sound designer or audio QA tester.
Sometimes having a portfolio with involement in indie titles can help you skip past this stage and get you into the next tier of jobs where you could be a sound effects designer or musical composer. There are a few other titles also at this tier but the two I mentioned were
the most prominent in my research. At this tier you interact much more directly with project than being a junior designer or QA tester. Once you've proven your skills and worked long enough you can be promoted to a senior sound designer or even a lead role if you really
put in the work!

2. Game artist is another very important role responsible for visuals and in this day and age visuals are extremely important whether it be stylized or realism you need to stand out to make your project seen. With this sort of field of work typically companies are less looking
for credentials and more so experience so most game artists will be self taught with a portfolio to back their skills to secure a job. The entry level positions here either a junior artist or a concept art assistant. Both of these take more of a backseat with the junior artist
usually working on smaller less important props and models. Once you've established some work artists usually branch off into various different specializations sometimes eparated by 2d and 3d or specializing in a specific type of work like character modeling. After this you'll
have to prove your competency with engine specific work (think shading and rigging) before you can be promoted to a senior or lead on the project!

3. Game designer is the role responsible for how a game actually plays the mechanics, pacing, and systems that make something feel fun or fair. To me this is what separates a forgettable game from one people still talk about years later
like how Dark Souls is remembered for its deliberate, punishing design rather than its graphics. The most common way in is through QA testing, since it teaches you how mechanics succeed or fail in practice. Design is also one of the more self taughtfriendly paths
so a portfolio of prototypes or game jam entries can carry real weight even without formal experience. From there, designers usually specialize level design and systems design came up most in my research, though narrative and combat design are common too.
At this stage you're doing much more hands on creative work, often picking up light scripting to prototype your own ideas. After that, it's a climb toward senior designer, then leadership roles like lead designer, creative director, or game director.

4. Producer's are responsible for keeping everything moving. Since they don't require many skills in the field they work in (Game dev in this case) they are often chosen from either outside fields like buisiness or they just pick someone that seems like a natural leader
that already works there. At an entry level I suppose a QA tester could be appropriate since it is one of the jobs they'll pick from when looking for a producer or you could end up a associate producer though its unlikely that will be your first position. At the mid level
there is a fair amount of variety with different sppecialists for different branches of a company with some like the production coordinator making sure communicaton between branches is running smoothly or a development producer that manages a team and keeps them on task to make
sure their portion of development is running smoothly. Finally at the top theres senior producers who oversee the entire project as a whole and manage budgets and smaller teams on top of it. Being a producer is also a good way to try to make your way to being the head of the
studio!

5. Game Programmers are often chosen for entry level positions based off a computer science degree (or other relevant degree) or based off of equivalent self taught experience. Junior programmers work under supervision on small aspects of projects typically with a predefined
end goal for their contribution. Often they are bug fixers. At the mid tier you move into a specialization like AI programming, gameplay programming, engine programming or graphics programmer. You have a lot of options to do what you like here. You get a lot more freedom and
ability to contribute with these positions. Finally you can end as a lead programmer or technical director. With these positions you'll have a small team working under you that you will direct and oversee.

For game programming the major disciplines I could find are: Gameplay programming where your responsible for mechanics movement and all the stuff that makes the game actually fun (Gameplay Programmer), Engine programming is all about performance and making sure everything
can run okay. It works within the architecture that everything else runs on. (Engine Programmer), Graphics programming is focused on visuals and making everything look nice and presentable or abiding by the game's art style (Graphics Programmer), AI programming is for the
non player characters. Basically everything else in the game that needs to move and make descisions is set up by the AI programmers (AI Programmer), Network programming is mostly for multiplayer games and handles getting everyone connected while trying to keep input delay
and other forms of lag to a minimum. This discipline also handles making anti-cheats (Network Programmer), Physics programming handles collision and how things react when contacting with eachother and how things move and sometimes the physics will be stylized for a more unique experience
(Physics Programmer), Tools programming is mostly to make the jobs of everyone else easier. Making stuff like level editors and asset pipelines that way the core code dosen't need to be touched as much to make new assets (Tools Programmer), Audio programming is for how sound
is used in the game like what triggers what audio and how does the audio travel though space (Audio Programmer), UI programming is for menu's and huds and all the things that give you the information you need to play the game and understand whats happening and the current state
of things. Think health bars menus and scoreboards (UI Programmer), Systems programming is for ensuring the build will run well on all platforms. Think Console Pc and mobile. The system programmers make sure the game runs well on all hardware its intended to be played on (Build Engineer).

It should be noted that it varies studio to studio what the same job will be called. Pretty often the word programmer and the word engineer are interchangeable.
